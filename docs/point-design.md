# 포인트 설계

고객이 가게에 충전해 둔 잔액(포인트)을 서버에 어떻게 저장하고 앱에 내려주는지 정리한 문서예요.
정해진 것과 아직 정할 것을 나눠 적었어요. 정책 값이 정해지면 이 문서부터 고쳐요.

## 1. 지금 범위

| 항목 | 상태 |
|---|---|
| 가게·포인트 묶음 테이블, `/api/wallet`이 실제 데이터를 돌려줌 | **구현됨** |
| 관리자 웹: 가게 추가·수정, 포인트 묶음 조회 | **구현됨** |

| 공유포인트 | 설계만. 넘겨주기인지 빌려주기인지부터 정해요 |
| 가게용 앱 (가게차감, 차감 알림, 오늘의 차감 내역) | 이 레포에 없어요. 기획은 피그마 `☆가게용-APP (복사)`의 9장(차감), 10장(알림센터), 16장(차감 내역)에 있어요 |
| 프랜차이즈 지점 | 05-07 지점 선택 화면을 만들 때 |

## 2. 용어

- **포인트**: 가게에 충전해 둔 잔액이에요. 단위는 `P`, 실제로 내는 돈은 `원`이에요.
- **충전포인트**(charge): 내가 할인된 금액으로 충전한 포인트예요. 현금처럼 쓰는 포인트라 유효기간이 없어요.
- **공유포인트**(shared): 다른 회원이나 그룹에게서 받은 포인트예요. 아직 만들지 않았어요.
- **서비스포인트**(service): 가게가 감사의 뜻으로 준 포인트예요. 기한이 있어요.
- 처음에는 '캐시'라고 불렀는데 개발 용어 cache와 헷갈려서 바꿨어요. 리뷰·이벤트 적립금은 두지 않아요.

## 3. 데이터 구조

```
stores (가게 = 포인트를 쓰는 단위)        point_lots (포인트 묶음 = 충전 1건 또는 서비스포인트 지급 1건)
- id                                    - user_id   → users.id  (기록이 있으면 회원을 지울 수 없음)
- name                                  - store_id  → stores.id (기록이 있으면 가게를 지울 수 없음)
- kind  cafe·food·bakery·beauty·shop    - type      charge, service
- address  주소 (비워 둘 수 있음)          - amount    처음 받은 포인트
- phone    전화번호 (비워 둘 수 있음)      - balance   남은 포인트
                                        - paid_won  충전할 때 낸 돈(원). 서비스포인트는 비움
charge_products (충전 상품)              - expires_on 이 날까지 쓸 수 있음. 충전포인트는 비움(기한 없음)
- store_id  → stores.id (가게를 지우면 함께 지움)
- amount    충전되는 포인트
- price_won 내는 돈(원). amount보다 클 수 없음
```

- **포인트는 가게마다 따로예요.** 충전한 포인트는 그 가게에서만 써요(시안 04-07).
- **프랜차이즈는 브랜드 하나가 가게 하나예요.** 충전한 포인트를 같은 브랜드의 모든 지점에서 써요(시안 05-07). 지점 목록은 지점 선택 화면을 만들 때 따로 둬요.
- **충전 1건이 묶음 하나예요.** 같은 가게에 두 번 충전하면 묶음이 두 개이고, 지갑에도 두 줄로 보여요.
- **충전포인트는 유효기간이 없어요.** 현금처럼 쓰는 포인트이기 때문이에요(2026-11-09 정함). 서비스포인트만 묶음마다 기한이 있어요.
- **다 쓰거나 기한이 지난 묶음도 지우지 않아요.** 아낀 금액, 이전 가게(05-08), 환불 계산에 써요.
- **결제 취소는 1일 안에, 그 뒤 환불은 수수료 1%예요**(2026-11-10 정함). 결제일로부터 1일 안에 그 결제로 충전한 포인트를 쓰기 전이면 결제를 취소해요. 그 뒤에는 환불 신청 가능 금액(원 결제 금액 − 쓴 포인트)에서 그 1%를 수수료로 빼고 환불해요(시안 04-07, 07-05). 할인받아 충전하고 많이 쓰면 이 금액이 0원 이하가 될 수 있어요(예: 50,000P를 47,500원에 충전하고 49,000P를 쓰면 −1,500원). 이때 어떻게 할지는 7장에서 정해요.
- **쓰기(차감)는 두 갈래예요**(2026-11-11 정함, 가게용 앱 기획 9장).
  - 고객차감: 손님이 손님 앱에서 금액을 넣고 직접 써요(시안 05-03 → 05-05 → 05-06). 메뉴를 골라 금액을 계산할 수도 있어요(05-04).
  - 가게차감: 사장님이 가게용 앱에서 손님 QR(05-02)을 스캔하거나 전화번호 뒤 4자리로 손님을 찾아, 금액을 넣고 차감해요.
- **손님이 쓰기를 누르면 바로 차감돼요.** 사장님 승인을 기다리지 않아요. 05-05에서 사장님과 금액을 함께 확인하는 것이 안전장치예요. 차감되면 사장님에게 알림이 가고, 가게용 앱의 오늘의 차감 내역에 고객차감으로 보여요.
- **서비스포인트부터 써요**(시안 05-06). 기한이 있는 포인트를 먼저 써서, 쓰지 못하고 사라지는 포인트를 줄여요. 같은 종류 안에서 어느 묶음부터 쓸지는 7장에서 정해요.
- **충전 상품은 가게가 정해요.** 예: 50,000P를 47,500원에. 할인율은 `(amount − price_won) ÷ amount`이고, 소수점은 버려서 실제보다 크게 보이지 않게 해요.
- 업종(`kind`)은 앱의 아이콘 묶음과 같은 다섯 가지예요. 시안 03-03의 세부 업종(한식, 분식 등)은 가게 찾기 필터를 만들 때 따로 둬요. 그때 업종을 DB 테이블로 옮겨서, 업종을 추가해도 앱을 다시 배포하지 않게 해요([#18](https://github.com/nambak/prepay_app/issues/18)). 그 전까지 앱은 모르는 업종을 일반 가게로 보여 줘요.

## 4. 앱 API

### `/api/wallet` (내 가게 탭 05-01)

응답 모양은 앱 `PointRepository`가 읽는 그대로예요.

- **쓸 수 있는 묶음**만 보여줘요: 남은 포인트가 있고, 기한이 없거나 `expires_on`이 오늘이거나 그 뒤인 묶음이에요. 마지막 날은 `days_left: 0`이고, 기한이 없는 충전포인트는 `days_left: null`이에요. 앱은 `null`이면 D-day를 그리지 않아요.
- **가게 순서**: 쓸 수 있는 묶음 중 가장 최근에 받은 묶음이 있는 가게가 위예요.
- **묶음 순서**: 충전 → 공유 → 서비스, 같은 종류는 기한이 빠른 것부터예요. 기한이 없는 충전포인트는 먼저 받은 것부터예요.
- **아낀 금액**(`saved_won`): 충전 묶음마다 `amount − paid_won`을 더해요. 다 썼거나 기한이 지난 묶음도 넣어요.
- **공유포인트**(`shared`)는 0, **방문 횟수**(`visit_count`)는 쓰기 기록이 없어서 0이에요. 앱은 0이면 방문 횟수를 숨겨요.
- 날짜는 서버 시간대 `Asia/Seoul` 기준이에요.

### `/api/stores` (가게찾기 03-01, 가게 상세 04-01)

- **목록**(`GET /api/stores`): 모든 가게를 등록한 순서로 `{"stores": [...]}`에 담아 줘요. 페이지를 나눌 때 정보를 덧붙일 수 있게 배열을 바로 주지 않아요. 가게마다 충전 상품 중 가장 큰 할인율(`max_discount_rate`)을 함께 주고, 충전 상품이 없으면 `null`이에요. 지역·거리 정렬을 만들 때 페이지로 나눠요.
- **상세**(`GET /api/stores/{id}`): 주소·전화와 충전 상품(`charge_products`)을 포인트가 작은 순으로 줘요. 상품마다 할인율(`discount_rate`)이 있어요.
- 둘 다 로그인해야 볼 수 있어요. 고객 앱이 로그인한 뒤에만 열리기 때문이에요.

### `POST /api/stores/{id}/charges` (충전 결제 04-07 → 충전 완료 04-08)

- **보내는 것**: `{"items": [{"charge_product_id": 1, "quantity": 2}]}`. 이 가게의 충전 상품만 고를 수 있고, 같은 상품은 한 줄에만 넣어요. 수량은 1~99예요. 99는 잘못 누른 큰 수를 막는 기술적인 상한이고, 충전 한도는 7장에서 정해요.
- **계산**: 포인트와 낼 돈은 앱이 보낸 값을 쓰지 않고, 서버가 그 가게의 충전 상품으로 계산해요.
- **묶음**: 고른 상품을 모두 합쳐 충전포인트 묶음 하나를 만들어요. 기한은 없어요.
- **결제**: 지금은 가짜 결제라서 바로 결제된 것으로 봐요. PG사가 정해지면 묶음을 만들기 전에 결제 승인을 받아요([#20](https://github.com/nambak/prepay_app/issues/20)).
- **같은 요청이 두 번 오면** 두 번 충전돼요. 앱은 결제하는 동안 버튼을 막고, PG를 붙일 때 주문번호로 중복 결제를 막아요.
- **실패 안내**: 앱은 4xx만 충전되지 않은 것으로 보고 '결제하지 못했어요'를 보여 줘요. 5xx나 응답이 없으면 서버가 충전한 뒤에 오류가 났을 수도 있어서, 다시 누르기 전에 내 가게에서 포인트를 먼저 확인하라고 안내해요.
- **응답**(201): `{"id", "store_name", "amount", "paid_won", "charged_at"}`. `charged_at`은 `2026-11-09T14:03:00+09:00`처럼 서버 시간대로 줘요.

## 5. 관리자 웹

- **가게**: 추가·수정만 해요. 포인트 기록이 있는 가게는 DB가 지우지 못하게 막아서 삭제 버튼은 두지 않아요. 주소·전화와 충전 상품도 가게 추가·수정 창에서 넣어요.
- **포인트**: 조회만 해요. 회원·가게로 찾고, 종류로 거를 수 있어요. 포인트는 충전·지급 기능으로만 생기고 관리자 웹에서는 만들거나 고치지 않아요.
- **회원**: 삭제 버튼을 뺐어요([auth-design.md](auth-design.md) 6장).

## 6. 테스트 데이터

`php artisan db:seed`는 관리자 계정(`admin@example.com`)과 고객 앱 테스트 계정(`test@example.com`)을 만들고, 테스트 계정에 가게 4곳과 포인트를 넣어요. 충전 상품은 포인트 묶음의 충전 금액과 맞췄고, 포인트도 충전 상품도 없는 가게(아침베이커리)도 하나 있어요. 비밀번호는 `DatabaseSeeder`와 `UserFactory`에 있어요.
`migrate:fresh`는 개발 DB를 지워요. `--env=testing`을 붙여도 `.env.testing`이 없으면 `.env`의 개발 DB를 써요.

## 7. 아직 정할 것

| 항목 | 선택지 / 메모 |
|---|---|
| 공유 방식 | 넘겨주기(받은 사람 것이 됨) / 빌려주기(보낸 사람 것으로 남고 끄면 못 씀, 시안 07-06 토글) |
| 서비스포인트 유효기간 기본값 | `[N]`일 (시안은 D-100). 충전포인트는 기한이 없어요 |
| 충전 한도 | 한 번에, 또는 가게별로 가질 수 있는 한도 `[N]`원. 지금은 상품마다 수량 99개까지만 받아요 |
| 환불 신청 가능 금액이 0원 이하일 때 | 환불 신청을 막기 / 0원으로 보고 남은 포인트만 없애기. 어느 쪽이든 수수료는 받지 않아요(0원의 1%) |
| 취소 기간 1일의 기준 | 결제 뒤 24시간 / 결제한 다음 날 끝까지. 환불 수수료의 1원 미만을 어떻게 할지도 함께 정해요 |
| 같은 종류 묶음 안에서 먼저 쓰는 순서 | 서비스포인트부터 쓰는 것은 정했어요(3장). 제안: 서비스포인트는 기한이 빠른 것부터, 충전포인트는 먼저 충전한 것부터. 그래야 방금 충전한 결제를 1일 안에 취소할 수 있어요 |
| 관리자 차감 | 가게용 앱 13-3 고객 상세에 '관리자 차감'이 있어요. 누가 언제 하는 차감인지 정해요 |
| 포인트 변동 기록 | 충전·쓰기·환불을 만들 때 묶음별 기록 테이블을 함께 만들어요 |
| 02-01 홈 친구 초대 배너 | "둘 다 5,000P" 이벤트 보상을 남길지. 리뷰·이벤트 적립금을 없앤 것과 맞지 않아요 |
